LuckyNumber V7.23.05 • Row First Percent Later Pro
Date: 2026-08-29

Goal
- Save one day: show today's History Hit/Miss first.
- Do not make the user wait for aggregate percentages or Profile Ranking.
- Keep latest-day work incremental and avoid full-profile hydration/rebuild.

Changes
1. Removed instant aggregate AI snapshot + Profile Ranking from the pre-History-paint save path.
2. History row status hydration now uses LNCanonicalHistory.peekRow() for exactly one row; it no longer calls canonical snapshot() / ensureRows(12) while painting the saved row.
3. Latest-save worker publishes any already-ready statuses first, advances WF by maxRows:1, then publishes the six row statuses.
4. Percentages / ranking refresh runs later (900 ms detached stage), after the row has been published.
5. Service worker explicitly caches hybrid-core-v72305.js to prevent a stale save worker after update.
6. No automatic all-profile bootstrap; no hydrateProfile(full:true) in latest-save path.

Validation
- JavaScript syntax: PASS (app, hybrid, canonical, service worker)
- E2E simulation: PASS 5/5
- Direct Source bridge: PASS 4/4
- Cool Save regression: PASS 5/5
- Row First / Percent Later regression: PASS 9/9

Expected UX
Save -> durable source commit -> History opens/updates -> today's Hit/Miss cells publish first -> aggregate % / Ranking refresh later.
No manual Rebuild required for a normal newest-day save.
