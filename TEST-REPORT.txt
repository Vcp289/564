BUG REPRODUCED
- When iOS/PWA was swiped away while History was the active page, the first cold-boot frame used the tiny UI-only boot mirror.
- That mirror intentionally stores no actualDraws, so History could visibly show “ยังไม่มีข้อมูล / ยังไม่มีผลย้อนหลัง” even though the durable History still existed.
- The full-state hydration happened only after the first frame, creating a false empty History state after reopen.

FIX
1) Added HISTORY COLD BOOT GUARD.
   - If currentView=history, restore the compact synchronous History-source journal BEFORE the first History render.
   - Restores Profile names/identity + actualDraws before exposing the page.
   - Falls back to MAIN loadState() when the compact journal is absent.
   - Full IndexedDB/model-cache hydration still runs afterward in background.
2) Strengthened Save durability.
   - Immediately after the primary Actual Result commit succeeds, writeHistorySourceSyncCheckpoint(state) runs synchronously.
   - If iOS kills the app immediately after Save, the newest result is available to the History cold-boot gate.
3) No model/formula change.
   - X3 Nested Pro 463, P18/P19, AI L, AI GL, Strict Prior-Only and AI Pick SHADOW logic unchanged.
