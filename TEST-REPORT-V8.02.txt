LuckyNumber V8.02 • iOS Resume Non-Blocking Pro
Regression focus: iPhone/PWA swipe/background/resume while Calculator is visible.

ROOT CAUSE CONFIRMED IN V8.01
- flushProfileNamesBeforeSuspend() ran on both pagehide and visibilitychange(hidden).
- It unconditionally called saveProfileMutationDurably().
- saveProfileMutationDurably() calls saveState(), which performs full-state JSON serialization
  and synchronous localStorage main write.
- Merely swiping/backgrounding could therefore process the complete History/WF/AI state
  on the iOS main thread even when no Profile name was edited.

V8.02 FIX
- Added profileNamesDirty guard.
- Full Profile durable save on suspend occurs only when a Profile name actually changed.
- Normal Calculator suspend uses saveUiStateFast() tiny boot snapshot only.
- Dedicated writeHistorySourceSyncCheckpointFast() suspend durability remains unchanged.
- Removed redundant async full History checkpoint from flushProfileNamesBeforeSuspend().
- V8.01 Calculate non-blocking fast save remains intact.

REGRESSION
- No formula/AUTO Route/History/WF/Ranking/X3/P18/P19 core changes.
- pro-core, auto-route, history-analysis-core, hybrid-core, x3-pro and CSS are byte-identical to V8.01.
- JS syntax check passed for all JS files.
- manifest/version JSON parse passed.
- Static suspend-path guard passed.

NOTE
- iOS/WebKit may still discard/reload a PWA under memory pressure. V8.02 removes LuckyNumber's
  own ordinary-suspend full-state synchronous write, which was the app-controlled freeze source.
