LuckyNumber V6.10.40-R2 — WF Fast Batch Audit

Goal
- Speed up image imports containing ~15 historical days.
- Preserve the exact Walk-Forward Prior-only / Anti-Leak methodology.

Performance change
1. evaluateFormulaWeighted now generates each sample formula status once per candidate formula.
2. 10/20/60/120/All windows aggregate the same precomputed statuses instead of rebuilding formula grids per window.
3. Exact-hit bonus uses the same status vector, eliminating another duplicate formula-grid pass.
4. Image-import save/table loops yield to the UI every 4 rows instead of forcing ~16ms wait on every row.

Unchanged safeguards / methodology
- WF population size remains 48.
- WF generations remain 8.
- Elite size remains 10.
- Adaptive-memory windows/weights unchanged.
- Same strict date ordering and prior-only training path.
- No Legacy History is promoted to trusted scoring.
- No current/future result is used to train its own prediction.
- Existing WF cache prefix is reused when startDate allows it.

Expected effect
- The main WF formula-scoring hot loop removes repeated grid construction across five memory windows plus the exact pass.
- Actual speedup depends on History size/device, but 15-day batch imports should be substantially faster while producing the same scoring semantics.
